Test your response-handling code before you connect it to a model provider. This guide turns [`mock_response`](/routehub/testing) into a runnable pytest suite. You will check ordinary responses, empty replies, synchronous and asynchronous streams, usage-only chunks, and exception handling. A network guard makes an unexpected socket connection fail the test instead of silently reaching a provider.

These are application contract tests. They check how your code consumes RouteHub results. They do not measure model quality, verify credentials, or establish that a provider accepts your request parameters.

## Prepare an isolated environment

Use Python 3.10 or later. From a new directory, create a virtual environment, activate it, and install the dependencies:

```bash
python -m venv .venv
# macOS / Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install "routehub==0.4.0" "pytest==9.1.1"
mkdir tests
```

Package installation needs internet access. The tests below do not need a provider account or API key. The examples were verified with RouteHub 0.4.0 and pytest 9.1.1 on Python 3.12. Keep that RouteHub pin when reproducing the result; rerun the suite when you upgrade. See [Installation](/routehub/installation) for other installation options.

## Reject unexpected network access

Save this as `tests/conftest.py`:

```python
import os
import socket

import pytest


@pytest.fixture(autouse=True)
def offline_only(monkeypatch):
    # Remove provider credentials from this test process only.
    for name in tuple(os.environ):
        if name.endswith("_API_KEY"):
            monkeypatch.delenv(name, raising=False)

    def reject_network(*args, **kwargs):
        raise AssertionError("Unexpected network access in an offline test")

    monkeypatch.setattr(socket, "create_connection", reject_network)
    monkeypatch.setattr(socket, "getaddrinfo", reject_network)
    monkeypatch.setattr(socket.socket, "connect", reject_network)
    monkeypatch.setattr(socket.socket, "connect_ex", reject_network)
```

The fixture runs automatically for every test under `tests/`. Pytest restores the patched functions and environment variables after each test. It does not edit your shell profile, `.env` files, or saved credentials.

Keep provider calls out of module-level imports and setup code that runs before this fixture. This guard covers Python socket operations during each test; it is not an operating-system network policy and does not cover subprocesses or native transports. Use your CI runner's network controls if you need process-wide isolation.

## Add the contract tests

Save this as `tests/test_routehub_offline.py`:

```python
import asyncio
import json
import socket

import pytest
import routehub


MODEL = "gpt-5.4-mini"
MESSAGES = [{"role": "user", "content": "Return the review decision."}]


def chunk_text(chunk):
    if not chunk.choices:
        return ""
    return chunk.choices[0].delta.content or ""


@pytest.mark.parametrize("reply", ["Approved.", "", "Approved.  Next step.\n"])
def test_completion_content(reply):
    result = routehub.completion(
        model=MODEL, messages=MESSAGES, mock_response=reply
    )
    assert result.choices[0].message.content == reply
    assert result.choices[0].finish_reason == "stop"


@pytest.mark.parametrize("reply", ["", "Approved.  Next step.\n"])
def test_stream_with_usage_chunk(reply):
    with routehub.completion(
        model=MODEL,
        messages=MESSAGES,
        mock_response=reply,
        stream=True,
        stream_options={"include_usage": True},
    ) as stream:
        chunks = list(stream)
    assert "".join(chunk_text(chunk) for chunk in chunks) == reply
    assert chunks[-1].choices == []
    assert chunks[-1].usage is not None
    assert any(
        chunk.choices and chunk.choices[0].finish_reason == "stop"
        for chunk in chunks
    )


def test_async_completion():
    async def run():
        result = await routehub.acompletion(
            model=MODEL, messages=MESSAGES, mock_response="Approved."
        )
        assert result.choices[0].message.content == "Approved."

    asyncio.run(run())


@pytest.mark.parametrize("reply", ["", "Approved after review."])
def test_async_stream(reply):
    async def run():
        stream = await routehub.acompletion(
            model=MODEL,
            messages=MESSAGES,
            mock_response=reply,
            stream=True,
        )
        async with stream:
            parts = [chunk_text(chunk) async for chunk in stream]
        assert "".join(parts) == reply

    asyncio.run(run())


def test_application_catches_rate_limit():
    simulated = routehub.RateLimitError("simulated limit")
    with pytest.raises(routehub.RateLimitError) as caught:
        routehub.completion(
            model=MODEL, messages=MESSAGES, mock_response=simulated
        )
    assert caught.value is simulated
    assert caught.value.status_code == 429


@pytest.mark.parametrize("reply", ['{"approved": true}', "not JSON"])
def test_application_parses_json(reply):
    result = routehub.completion(
        model=MODEL, messages=MESSAGES, mock_response=reply
    )
    content = result.choices[0].message.content
    if reply == "not JSON":
        with pytest.raises(json.JSONDecodeError):
            json.loads(content)
    else:
        assert json.loads(content) == {"approved": True}


def test_network_guard_is_active():
    with pytest.raises(AssertionError, match="Unexpected network access"):
        socket.create_connection(("example.invalid", 443))
```

Run the suite from the directory containing `tests/`:

```bash
python -m pytest -q tests/test_routehub_offline.py
```

The expected result is **12 passed**. Parameterized cases count separately, including empty synchronous and asynchronous streams. `asyncio.run()` drives each asynchronous example, so you do not need `pytest-asyncio` or a shared event loop for this suite. The final test checks the guard itself: its patched function raises before a connection is attempted.

## Choose assertions that survive upgrades

Assert the content and fields that your application uses. The mock generates response identifiers and creation timestamps at runtime, so a snapshot of the entire object would change even when your application behavior stays correct. Likewise, do not use mock token counts to estimate a production bill: they are approximations.

Streaming responses need more care than a single response. Some chunks carry a role or finish reason without text. A final usage chunk can have an empty `choices` list. The `chunk_text()` helper checks that list before indexing it, and the stream test includes a usage chunk to exercise that branch. Compare the reconstructed text, including whitespace, rather than requiring a particular number of chunks or provider-specific token boundaries.

Test asynchronous response handling separately from synchronous handling. Await `acompletion()` first, then iterate its streaming result with `async for`. The context managers in the examples also exercise the stream cleanup interface your application should use when iteration ends early.

## Keep mock and provider tests separate

Passing an exception as `mock_response` raises that exception directly. The rate-limit test verifies that application code can catch the expected error type and inspect its status. It does not exercise RouteHub's HTTP retry loop, provider error translation, fallback configuration, or a real timeout. Testing those behaviors needs a controlled fake HTTP transport or a separately configured integration test.

Similarly, returning a JSON string does not enforce a provider schema. The JSON cases verify your own parsing behavior, including malformed output. Add your application's schema validator after parsing when your contract requires specific fields or types. See [Structured output](/routehub/structured-output) for provider-facing configuration.

Mock calls bypass model resolution. A successful mock for `MODEL` does not establish that the model exists or that a provider supports it. Check routing separately using the [model catalog](/routehub/model-catalog), and keep any real-provider smoke test outside this offline suite with explicit credentials and a deliberate invocation. Do not automatically rerun a failing mock test against a paid provider.

When you adapt this suite, replace the small parsing helpers with calls to your application's actual response-handling functions. Keep the network guard, empty-response cases, usage-only chunk handling, and malformed-output checks so that regressions fail locally before you opt into an integration run.
